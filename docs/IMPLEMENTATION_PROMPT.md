# PLAY BASEBALL 구현 프롬프트

아래 프롬프트를 Codex 또는 다른 개발 에이전트에 전달하면 현재 프로토타입을 이어서 개발할 수 있습니다.

## 마스터 프롬프트

당신은 생활체육 매칭 플랫폼을 만드는 시니어 제품 엔지니어다. `PLAY BASEBALL`은 팀에 가입하지 않아도 사용자가 날짜·지역·경기 수준을 확인하고 희망 포지션 1~3지망을 선택해 생활야구 경기에 참가하는 모바일 우선 서비스다.

현재 Next.js App Router + TypeScript + Tailwind CSS 기반 PWA 프로토타입이 있다. 기존 디자인과 접근성을 유지하면서 작은 수직 기능 단위로 구현하라.

핵심 사용자 흐름:

1. 지역과 날짜로 모집 중인 경기를 탐색한다.
2. 경기 장소, 시간, 수준, 참가비, 잔여인원과 필요한 포지션을 확인한다.
3. 희망 포지션을 선호 순서대로 최대 3개 선택한다.
4. 로그인 후 참가 신청하고 결제한다.
5. 취소 기한, 날씨 상태와 최종 포지션 배정을 알림으로 확인한다.
6. 경기 당일 체크인하고 종료 후 간단한 평가를 남긴다.

도메인 원칙:

- 실력 수준(PLAY LEVEL), 약속 이행(Reliability), 투수·포수 인증을 서로 다른 데이터로 관리한다.
- 경기 개설은 PLAY OFFICIAL, HOST, VENUE 세 유형을 지원하되 첫 MVP에서는 관리자 생성 경기부터 구현한다.
- 경기 시작 72시간 전까지 무료 취소, 이후 취소는 대체 참가자 충원 상태에 따라 처리한다.
- 날씨·운영 사유 취소는 원 결제수단 전액 환불을 기본으로 한다.
- 현금성 자체 충전지갑은 구현하지 않는다. 일반 결제와 활동 보상용 포인트를 분리한다.

개발 원칙:

- Server Component를 기본으로 하고 상호작용이 필요한 말단 컴포넌트만 Client Component로 만든다.
- 모든 서버 액션과 API에서 인증·인가와 입력 검증을 수행한다.
- 모바일 375px부터 데스크톱까지 가로 스크롤 없이 동작하게 한다.
- 터치 영역은 최소 44×44px, 텍스트 대비는 WCAG AA, 키보드 탐색과 명확한 포커스 표시를 지원한다.
- 로딩, 빈 상태, 오류, 중복 신청, 마감, 취소와 환불 상태를 명시적으로 처리한다.
- 기능 구현 후 lint, typecheck, production build와 핵심 사용자 흐름 테스트를 실행한다.

다음 작업만 구현하고 범위를 넓히지 마라: `[여기에 한 번에 구현할 작업을 입력]`

완료 보고에는 변경 파일, 사용자 행동의 전후 차이, 검증 결과와 남은 위험을 포함하라.

## 추천 구현 순서

1. Supabase 스키마와 인증
2. 경기 목록·상세 서버 데이터 연결
3. 포지션 1~3지망 참가 신청
4. 정원·중복 신청 트랜잭션
5. 대기자와 취소 처리
6. 결제대행 연동 전 테스트 결제 상태머신
7. 운영자 경기 생성·참가자 관리
8. 알림과 날씨 검토 상태
9. 체크인·Reliability
10. 실제 PG, 환불과 정산

## 첫 번째 후속 작업 프롬프트

Supabase를 사용해 회원, 선수 프로필, 구장, 경기, 참가 신청, 희망 포지션 테이블을 설계하고 마이그레이션을 작성하라. 참가 신청 시 정원 초과와 중복 신청을 데이터베이스 트랜잭션으로 막고, 1~3지망 순서가 보존되게 하라. 샘플 데이터를 추가하고 현재 홈 화면의 정적 경기 목록을 Server Component 데이터 조회로 교체하라. 결제와 환불은 아직 실제 PG에 연결하지 말고 `pending`, `paid`, `cancelled`, `refunded` 상태만 모델링하라.
